# Лист персонажа Long Story Short (.json)

Цель: после разговора выдать один файл `<имя>.lss.json`, который импортируется в LSS и сразу
работает: числа считаются, заклинания находятся, предметы дают свои бонусы, счётчики щёлкают.

Все пути ниже - относительно папки этого скилла (там, где лежит этот SKILL.md). Скрипт запускай
по полному пути: `python <папка скилла>/scripts/lss.py ...` (на macOS/Linux может быть `python3`).

- `scripts/lss.py` - сборка черновика в итоговый файл и проверка (схема + перекрёстные ссылки);
- `reference/draft-format.md` - как писать черновик. **Прочитай перед первым черновиком**;
- `templates/draft-template.json` - рабочий пример черновика (волшебник 3 уровня);
- `templates/example-*.lss.json` - готовые файлы, которые импортируются в LSS;
- `reference/character.schema.json` - официальная схема `data` (для спорных полей);
- `reference/srd-spell-slugs-2014.json`, `-2024.json` - заклинания SRD с id, кругом и классами.

Схема и справочники - копия с сайта на 23.10.2026. Если импорт ругается на поле, которого
скрипт не знает, обнови их: `python <папка скилла>/scripts/lss.py refresh` (нужен интернет).
Первоисточник: https://longstoryshort.app/doc/developers/characters/

Перед первой сборкой проверь зависимости: `python -c "import jsonschema, PIL"`. Если чего-то нет,
попробуй `pip install jsonschema pillow`. Не вышло (нет сети) - собирай всё равно: скрипт
предупредит, что проверка схемой пропущена, и тогда тем внимательнее сверяйся с `draft-format.md`.

## Порядок работы

### 1. Собери данные - максимум из того, что дали

Сначала вытащи всё из описания, анкеты или картинки. Анкеты игроков обычно отвечают на вопросы
об образе (страхи, ценности, тайны, долги, вайб), а не о механике: это материал для характера,
привязанностей, слабостей и предыстории, а механику под этот образ подбираешь ты.

Недостающее спроси одним сообщением, к каждому вопросу предложи вариант по умолчанию, чтобы
можно было ответить «да». Если человек просит просто сгенерировать или «придумай сам» - не
спрашивай, решай и перечисли принятые решения в итоговом сообщении. Обычно нужно:

- редакция правил: 2014 (PHB, dnd.su) или 2024. По умолчанию 2014;
- класс, подкласс, уровень (по умолчанию 1); мультикласс - см. ниже;
- раса (вид) и предыстория;
- характеристики: свои числа, стандартный набор 15/14/13/12/10/8 или покупка очков;
- навыки на выбор класса, языки, инструменты;
- снаряжение: стартовое по классу или своё, есть ли магические предметы;
- заклинания: выбрать самому под концепцию или по списку пользователя;
- имя, мировоззрение, внешность, характер, предыстория - если нет, придумай под концепцию;
- портрет: если прислали картинку, вставь её в лист (см. «Портрет»).

Личные контакты из анкеты (телеграм, телефон, почта) в лист не переноси: лист видят другие игроки.

### 2. Посчитай механику по правилам выбранной редакции

Лист LSS, собранный не визардом, ничего не знает о классах и расах: что не записал - того нет.
Поэтому всё считаешь сам, а в лист пишешь итог.

- **Характеристики** - итоговые значения с расовыми (2014) или предысторийными (2024) бонусами
  прямо в `stats`. Отдельные слои бонусов для этого не заводи.
- **Хиты**: максимум кости на 1 уровне + среднее (кость/2+1) за каждый следующий +
  модификатор Телосложения × уровень + прибавки (холмовой дварф, черта «Крепкий»).
- **КД** - формулой в `vitality.ac`: без доспеха `10+[DEX]`, кожаный `11+[DEX]`,
  проклёпанная кожа `12+[DEX]`, нагрудник `14+min([DEX],2)`, полулаты `15+min([DEX],2)`,
  кольчуга `16`, латы `18`, защита без доспехов варвара `10+[DEX]+[CON]`, монаха `10+[DEX]+[WIS]`,
  магический доспех `13+[DEX]`. Щит - `vitality.shield: true`, а не +2 в формуле.
- **Навыки** - класс + предыстория + раса; экспертиза (`2`) у плута и барда.
- **Скорость, тёмное зрение, размер** - по расе (у полуросликов и гномов `small` и 25 фт.).
- **Заклинания** - количество заговоров и известных/подготовленных по таблице класса.
  Выбирай из SRD, тогда они точно найдутся: `lss.py spells --edition 2014 --class wizard --max-level 2`.
  Не-SRD заклинание (Hex, Booming Blade, всё из Таши/Ксанатара) оставляй, только если пользователь
  настаивает, и предупреди: появится, только когда игрок добавит его в свой Гримуар.
- Ячейки, спасброски класса, кость хитов, бонус мастерства, заклинательная характеристика
  выводятся скриптом сами, если класс из SRD. Для мультикласса и необычных случаев задай их явно.
- Заговор-атаку (Мистический заряд, Огненный снаряд) удобно добавить и строкой в `weaponsList`
  с `ability` заклинательной характеристики - тогда бросок атаки и урона в один клик.

### 3. Разложи предметы и умения по листу

Отдельной сущности «предмет» в LSS нет. Предмет раскладывается так:

| Что | Куда |
|---|---|
| Любое снаряжение, включая магические предметы с описанием | `text.equipment` списком |
| Оружие | `weaponsList`: `dmg` с модификатором (`1к8+[STR]`), `dmgType`, свойства в `notes`, `ability` (`dex` у фехтовального/дальнобойного, если ловкость выше) |
| Оружие +1 | то же оружие с явным `id` + два бонуса `weapon.<id>.attack` и `weapon.<id>.damage`, `source: "Длинный меч +1"` |
| Доспех | формула `vitality.ac` (см. выше), владение в `prof` |
| Предмет с настройкой | строка в `attunementsList` с явным `id` + его бонусы с `source: { "kind": "attunement", "refId": "<id настройки>", "label": "..." }` - тогда галочка настройки включает и выключает бонусы |
| Кольцо/плащ защиты | бонусы `ac` и `save.all` по +1 |
| Жезл договорника, жезл +N | бонусы `spellAttack` и `spellDC` |
| Пояс силы великана | бонус `stat.str.score` с `mode: "set"` и значением |
| Заряды (палочка, зелья, стрелы) | ресурс с `max`, описание в `notes` |

Умения класса, расы, черты - текстом в `text.traits` (жирное название + описание). Умения с
ограниченным числом использований - ресурс (`isShortRest` / `isLongRest`, формула в `maxExpr`,
например `max(1,[CHA])` или `[PROF]`) и строка `[[resource:<id>]]` сразу под описанием умения.
Числовые прибавки от умений и черт - в `bonuses` с подходящим `source.kind` (`classFeature`, `feat`,
`origin`, `background`). Полный список целей бонусов (`target`) - в схеме, `definitions.BonusTarget`.

### 4. Портрет

LSS хранит аватар ссылкой на свой сервер, а загрузить туда можно только из аккаунта игрока.
Поэтому картинка встраивается прямо в файл: в черновике `"avatar": "<путь к картинке>"`, скрипт
сам сделает JPEG и WebP до 512 px. Аватар на листе квадратный, так что сначала вырежи квадрат
с лицом (Pillow, `Image.crop`), посмотри на результат и только потом укажи его в черновике.
Скрипт при этом выдаёт предупреждение о неофициальном формате - это ожидаемо; скажи игроку,
что если портрет не покажется, его можно загрузить кнопкой аватара на листе.

### 5. Черновик -> сборка -> проверка

1. Прочитай `reference/draft-format.md` и `templates/draft-template.json`.
2. Запиши черновик `<имя-латиницей>.draft.json` туда, куда сохраняешь файлы для пользователя
   (в локальном агенте - рабочий каталог или папка, которую назовёт пользователь; в облачной
   песочнице - папка, из которой пользователь скачивает файлы, например `/mnt/user-data/outputs`).
   Картинку портрета положи рядом.
3. Собери: `python <папка скилла>/scripts/lss.py build <черновик>`.
   Получится `<имя>.lss.json` рядом с черновиком.
4. `[X]` - ошибка, файл не записан: правь черновик и собирай снова, пока ошибок не станет 0.
   `[!]` - предупреждение: разберись с каждым, исправь или осознанно оставь и скажи пользователю.
   `[i]` - что скрипт вывел сам; проверь, что это то, что задумано.

Итоговый файл руками не правь: правки - в черновик и пересборка. Чужой или старый файл можно
проверить без сборки: `lss.py validate <файл.json>`.

### 6. Отдай результат

- сам файл `.lss.json` (и черновик - пригодится, когда персонаж поднимет уровень);
- короткая сводка: класс/уровень, характеристики, хиты, КД, ключевые предметы, заклинания;
- принятые за пользователя решения и оставшиеся предупреждения (особенно не-SRD заклинания);
- как загрузить: в LSS импорт персонажа из файла .json.

## Чего не делать

- Не писать `data` вложенным объектом - только JSON-строкой (это делает скрипт).
- Не писать производные поля: модификаторы характеристик, итоговые бонусы навыков, `coins.total`,
  `resolvedMax`, `spells.pending`, `spells.granted` (его пишет только визард LSS).
- Не использовать устаревшие `bonusesSkills` / `bonusesStats`.
- Не писать формулы со строчными переменными в числовых полях (`10+[dex]` считается как 10).
- Не придумывать типы узлов текста: незнакомый узел роняет отрисовку всего блока.
- Не заполнять `conditions` у нового персонажа.

## Мультикласс

`info.charClass` - строкой вида «Паладин 6 / Колдун 2», `id` - основного класса, `level` - общий.
Ячейки задай явно: обычные по таблице мультикласса в `data.spells`, ячейки договора - в
`data.spellsPact`. Кости хитов разных типов - `vitality.hp-dice-multi`:
`{ "d10": { "max": 6, "current": 6 }, "d8": { "max": 2, "current": 2 } }`. Заклинания второго
класса проверяй по его списку сам: скрипт сверяет только с основным классом.
