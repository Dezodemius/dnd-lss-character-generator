# Черновик для `lss.py build`

Черновик - это лист LSS в упрощённой записи. Скрипт сам дописывает служебные поля
(`name` в обёртках, `baseStat` у навыков, `id` у списков), превращает текст в документ
редактора, резолвит заклинания и упаковывает `data` в JSON-строку. Всё, что не упрощено,
пишется ровно как в официальной схеме `reference/character.schema.json`.

Полный рабочий пример: `templates/draft-template.json`.

## Верхний уровень

| Поле | Что писать |
|---|---|
| `edition` | `"2014"` или `"2024"` - редакция правил. Определяет, в каком SRD ищутся заклинания |
| `sheetEdition` | вёрстка листа, по умолчанию как `edition` |
| `spells.prepared` | известные / подготовленные заклинания, заговоры тоже здесь |
| `spells.book` | только у волшебника: всё, что записано в книге |
| `data` | содержимое листа (ниже) |

Заклинание можно указать как угодно: слаг (`cure-wounds`), английское имя (`Cure Wounds`),
русское имя из базы LSS (`Исцеление ран`) или `Исцеление ран [Cure Wounds]`. Найденное в SRD
скрипт записывает id из базы LSS. Не найденное, но латиницей - остаётся слагом с предупреждением
(найдётся у игрока, только если оно есть в его гримуаре). Не найденное и только по-русски -
ошибка: сервер такое не сведёт.

Русские имена в базе - как на dnd.su / в переводе LSS. Если сомневаешься, проверь:
`python lss.py spells --edition 2014 --search огн`.

## data: сокращения

| Поле | Сокращение | Во что превращается |
|---|---|---|
| `name` | `"Имя"` | `{ "value": "Имя" }` |
| `info.<поле>` | `"Жрец"`, `3` | `{ "name": "<поле>", "value": ... }` |
| `info.charClass` | название класса по-русски или по-английски | плюс `id` (`cleric`), если класс из SRD |
| `info.experience` | `900` или `"6 500"` | число |
| `info.size` | `"medium"` | `{ "value": "medium" }`, по умолчанию medium |
| `subInfo.<поле>` | строка | `{ "name", "value" }` |
| `stats` | `{ "str": 15, "Ловкость": 14 }` | `{ "name", "score" }` для всех шести |
| `saves` | `["con", "wis"]` | все шесть с `isProf`. Не указано - по классу |
| `skills` | `["stealth", "Скрытность"]` или `{ "stealth": 2 }` | все 18 навыков, `1` - владение, `2` - экспертиза |
| `vitality.<поле>` | `"hp-max": 24`, `"ac": "16"` | `{ "value": ... }`; числа в ac/speed/initiative - строкой |
| `vitality.shield` | `true` | `{ "value": true, "mod": "2" }` |
| `spellsInfo` | `{ "ability": "wis" }` или пропустить | `base.code`; у заклинателя по умолчанию по классу |
| `spells` (ячейки) | `{ "1": 4, "2": 2 }` или пропустить | `slots-N`; пропущено - посчитается по классу и уровню |
| `prof` | `["armor-light", "shield", "simple", "martial"]` | чекбоксы владения доспехами и оружием |
| `coins` | `{ "gp": 15 }` | все номиналы, остальные 0 |
| `weaponsList[]` | `{ "name": "Булава", "dmg": "1к6+[STR]", "dmgType": "дробящий", "notes": "..." }` | обёртки, `id`, `isProf: true`, `ability: "str"` |
| `attunementsList[]` | `"Кольцо защиты"` или `{ "id", "value" }` | `{ id, checked: true, value }` |
| `bonuses[]` | `{ "label", "target", "value", "source" }` | `id`, `mode: "add"`; строка в `value` уходит в `expr`; `source: "Имя предмета"` = `{ kind: "item", label }` |
| `resources` | массив `{ "id", "name", "max", "isShortRest", "isLongRest", "location" }` | словарь по `id`, `current = max`, виджет в тексте (см. ниже) |
| `text.<блок>` | строка или массив строк | документ редактора |
| `avatar` | путь к картинке (относительно черновика) | `{ jpeg, webp }` data-URI, до 512 px. Нужен Pillow |

Аватар: официально LSS хранит ссылки на свой сервер, а загрузка туда требует входа в аккаунт,
поэтому картинка встраивается прямо в файл. Перед этим сделай квадратный кроп с лицом
(аватар на листе квадратный/круглый). Если в LSS картинка не покажется, игрок загружает её
кнопкой аватара на листе, остальное от этого не зависит.

Не указано и выводится само: `proficiency` (по уровню), `hit-die` (по классу), `hp-current`
(= максимум), `hp-dice-current` (= уровень), спасброски, заклинательная характеристика и ячейки
(по классу), `speed` 30, `ac` `10+[DEX]`.

Если хочется посмотреть, во что развернулся черновик: `build ... --debug` пишет рядом
`*.debug.json` с `data` объектом.

## Текст

Строка с `\n` или массив строк. Понимается:

- `- пункт` / `* пункт` - маркированный список; `1. пункт` - нумерованный;
- `**жирный**` внутри строки;
- `## Заголовок` - жирная строка (настоящих заголовков редактор не знает);
- `[[resource:<id>]]` отдельной строкой - виджет ресурса-счётчика;
- пустые строки пропускаются.

Ничего другого (цитаты, таблицы, картинки, html) нет: незнакомый узел роняет отрисовку всего
блока. Если ресурс указан, но его `[[resource:id]]` нет в тексте, скрипт сам добавит виджет в
конец блока `location` (по умолчанию `traits`).

Ключи блоков задаёт шаблон листа. Точно есть (официальный пример): `traits`, `equipment`,
`personality`. Схема называет также: `attacks`, `feats`, `prof`, `ideals`, `bonds`, `flaws`,
`features`, `background`, `quests`, `allies`, `appearance`, `items`, `notes-1`..`notes-6`.
Если после импорта какого-то блока не видно - перенеси его текст в `traits` или `equipment`.

## Формулы

Числовые поля (`ac`, `speed`, `initiative`, `shield.mod`, `maxExpr` ресурса, `expr` бонуса,
`bonusExpr` навыка): переменные строго заглавными - `[STR] [DEX] [CON] [INT] [WIS] [CHA] [PROF] [LVL]`
(это модификаторы, не значения). Функции: `floor ceil round abs min max`. Костей здесь нет.
Пример: `13+min([DEX],2)`, `[PROF]*2`, `max(1,[CHA])`.

Урон оружия (`dmg`): кости `1к8` или `1d8`, регистр переменных не важен, можно `2к6+[STR]`.
Слово вместо переменной (`1к6+сила`) не бросится.
